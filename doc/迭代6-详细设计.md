## 1. 概述

### 1.1 目标
实现真人 WebSocket 实时 1v1 对战：匹配成功 → 双方同网格同时间对战 3 分钟 → 分数实时广播 → 结算判胜负。这是技术难度最高的迭代。

### 1.2 可运行状态
大厅 → 实时对战 → 匹配动画；两个 H5 标签页匹配成功，同网格开局（3-2-1 倒计时），3 分钟对战双方分数条实时同步；时间到结算页胜负对比（含稀有词数/连击峰值 tie-break）；断线 30s 内重连恢复；匹配 30s 超时提示未匹配。

### 1.3 范围
- **In**：大厅首页（GDD §6.1 P0）、WS 房间模型、Redis 匹配队列、同网格下发、实时计分广播（增量）、服务端权威计时、断线重连（30s）、matches/match_players 落库、前端对战页 + 对战结算对比、后端单测
- **Out**：AI 兜底（技术债 #9 → 迭代 8）、4 人混战/段位赛（→ 8）、好友挑战/每日挑战/排行榜（→ 7）、对战过程可见对方词（GDD §4.2.2 防抄：仅分数条）

### 1.4 对齐 GDD
- §4.2.2 实时对战（匹配/同网格/防抄/得分广播/结算 tie-break）
- §6.1 信息架构（大厅首页 P0）
- §7.4.3 matches 对局表
- §7.7 实时对战架构（匹配 → 开局 → 对局 → 结束；断线 30s）

## 2. 总体架构

```
玩家 A ─┐                     ┌─ 玩家 B
        ├─ WebSocket 房间 ────┤
        └─ GameGateway ───────┘
              │ userIdToClient Map
        MatchService（房间 Map + 计时 + 胜负 + 落库）
              │
          Redis（match_session:A / match_session:B + match:{id} 元数据）
              │
          PostgreSQL（matches + match_players）
```

### 2.1 核心决策：每玩家独立 `match_session`（最大复用）

**对战不新建计分通道，复用迭代 5 的 `match_session` 全链路**：

- 配对成功时，为每个玩家各建一个 `match_session:{sid}`（复用 `GameService.getGrid` 逻辑），会话 hash 增加 `matchId` 字段
- 客户端提词仍发 `submit_word`（带自己的 sid）→ `GameService.submitWord` 原逻辑不动（路径/拼字/潜在词池/连击/计分）
- 结算复用 `GameService.endGame`（已含图鉴批量收集 + unfoundWords 计算）
- **perfect 提前结束仅限单人**：`submitWord` 检测到 `session.matchId` 存在时跳过 perfect 分支（对战固定 3 分钟，不提前结束）

### 2.2 模块依赖（循环依赖处理）

`GameGateway`（GameModule）需要 `MatchService` 广播/断线通知；`MatchService`（MatchModule）需要 `GameService.getGrid` 建会话 + `GameGateway` 广播。**双向 `forwardRef`**：

```typescript
// game.module.ts
imports: [ ..., forwardRef(() => MatchModule) ]
exports: [GameService, GameGateway]

// match.module.ts
imports: [
  forwardRef(() => GameModule), GridPoolModule, DictionaryModule, AuthModule,
  TypeOrmModule.forFeature([MatchEntity, MatchPlayerEntity]),
]
controllers: [MatchController]
providers: [MatchService]
exports: [MatchService]
```

### 2.3 连接与广播

- `GameGateway` 新增 `userIdToClient = new Map<number, WebSocket>()`（`handleConnection` 注册、`handleDisconnect` 删除；clientData WeakMap 保留）
- `MatchService` 持有 `rooms: Map<matchId, MatchRoom>`；所有广播经 `GameGateway.broadcastToUser(userId, event, data)` 发送（ws 原生 `client.send`，JSON 帧）

## 3. 数据模型（PostgreSQL）

### 3.1 `matches`（对齐 GDD §7.4.3）

```typescript
@Entity('matches')
export class MatchEntity {
  @PrimaryColumn('uuid') id!: string
  @Column({ type: 'varchar', length: 16, default: 'pvp_1v1' }) type!: string
  @Column({ type: 'varchar', length: 64 }) gridSeed!: string      // grid_pool.id（gridUuid）
  @Column({ type: 'jsonb' }) grid!: string[][]                    // 双方同网格
  @Column({ type: 'jsonb' }) targetWords!: string[]
  @Column({ type: 'varchar', length: 16, default: 'ongoing' }) status!: string // ongoing/finished
  @Column({ type: 'bigint', nullable: true }) winnerId!: number | null
  @Column({ type: 'timestamptz' }) startedAt!: Date
  @Column({ type: 'timestamptz', nullable: true }) endedAt!: Date | null
}
```

### 3.2 `match_players`（GDD 注释：对局玩家分数落库）

```typescript
@Entity('match_players')
export class MatchPlayerEntity {
  @PrimaryGeneratedColumn() id!: number
  @Column('uuid') matchId!: string
  @Column({ type: 'bigint' }) userId!: number
  @Column({ type: 'int', default: 0 }) score!: number
  @Column({ type: 'int', default: 0 }) rareCount!: number   // 稀有词数（idiom+rare）
  @Column({ type: 'int', default: 0 }) maxCombo!: number
  @Column({ type: 'smallint' }) rank!: number               // 1 胜 / 2 负（平局皆 1）
  @Column({ type: 'varchar', length: 16 }) sid!: string     // 对应 match_session
}
```

## 4. 匹配服务

### 4.1 Redis 队列

- 入队：`POST /match/queue`（JWT）→ 校验不在其他队列/房间 → `LPUSH match_queue:{rankTier} userId` + `HSET match_queue_meta:{userId} {tier, enqueuedAt}` → 触发一次配对扫描
- 轮询：`GET /match/queue` → 返回 `queued`（含已等待秒）/ `matched`（含 matchId + 对局信息）/ `timeout`（等待 >30s，出队）
- 取消：`DELETE /match/queue` → 出队 + 删 meta

### 4.2 配对扫描

`MatchService` 启动 `@Interval(1000)` 扫描所有 tier 队列（tier 1-7）：

1. 每队列成对 `RPOP` 两个 userId（或从头取 2 个），配成一对
2. 取不出 2 人则保留（同 tier 优先；不足时跨 tier ±1 合并扫描）
3. 扫描中清理超时（enqueuedAt > 30s）的等待者 → 状态置 timeout，由客户端轮询消费

### 4.3 配对成功（`setupMatch(tier, userA, userB)`）

1. `gridPoolService.acquire('standard')` 取一张网格（对战固定 standard 5×5，决策 #1）
2. 建 `MatchEntity`（status ongoing、gridSeed=gridEntity.id、grid、targetWords）
3. 为 A/B 各建 `match_session`（复用 `GameService.getGrid` 返回的 sid），再 `HSET match_session:{sid} matchId`（决策 #2）
4. 建房间 `rooms.set(matchId, MatchRoom)`（status: countdown，players 两方 userId + connected 标记）
5. 向双方广播 `match_start`（含 grid/size/duration=180/对手昵称+段位/己方 sid）
6. 3s 后广播 `match_countdown`（3-2-1）→ 状态切 playing → 启动主计时

```typescript
interface MatchRoom {
  matchId: string
  difficulty: string
  grid: string[][]
  size: number
  duration: number            // 180
  players: Map<number, {    // key: userId
    sid: string
    clientConnected: boolean
    disconnectTimer?: NodeJS.Timeout
  }>
  status: 'countdown' | 'playing' | 'finished'
  remainingSec: number
  timer?: NodeJS.Timeout       // 每秒 tick
}
```

## 5. 对局生命周期

### 5.1 服务端权威计时

- `MatchService` 每秒 `tick(matchId)`：`remainingSec--` → 广播 `match_tick {remainingSec, scores}`（双方 score/combo 从各自 `match_session` 读，pipeline 批量）→ 归零时 `finishMatch`
- 玩家分数变更时（submit_word 后）立即额外广播一次（增量感知 <1s）

### 5.2 提词广播（GameGateway.submit_word 扩展）

```typescript
// handleSubmitWord 内，submitWord 成功后：
const session = await redis.hgetall(`match_session:${sid}`)
if (session?.matchId) {
  this.matchService.broadcastScore(session.matchId)  // 读双方 → 广播 match_tick + 对手得分飘字
}
```

- 广播内容**只含分数/连击增量，不含词**（GDD §4.2.2 防抄，决策 #4）

### 5.3 胜负判定（GDD §4.2.2）

```typescript
function decideWinner(a, b): 1 | 2 | 0 {   // 1=A胜 2=B胜 0=平
  if (a.score !== b.score) return a.score > b.score ? 1 : 2
  if (a.rareCount !== b.rareCount) return a.rareCount > b.rareCount ? 1 : 2
  if (a.maxCombo !== b.maxCombo) return a.maxCombo > b.maxCombo ? 1 : 2
  return 0
}
// rareCount = endGame 结果 foundWords 中 rarity ∈ {idiom, rare} 的词数
```

### 5.4 结算落库（`finishMatch(matchId)`）

1. 双方分别 `gameService.endGame(sid)`（图鉴批量收集 + found/unfound 数据）
2. 计算 rareCount/maxCombo → `decideWinner`
3. 更新 `MatchEntity`（status=finished、winnerId、endedAt）
4. 写 `match_players` 两行（rank 1/2；平局皆 rank 1，winnerId=null）
5. 广播 `match_end {matchId, winnerUserId, my:{...}, opponent:{...}, tieBreak}`（双方数据各自包装，含 foundWords 前几高亮供结算页展示）
6. 清 `match_session`（TTL 自然过期即可）、删房间、清 queue meta

## 6. 断线重连

- `GameGateway.handleDisconnect`：若 userId 在房间中 → `players.get(userId).clientConnected = false` + 启动 30s 定时器；超时 → 该方判负（`finishMatch`，winnerId 对面）
- 客户端重连：WS 指数退避重连（迭代 5 已有）→ 成功后发 `match_join {matchId}`
- `GameGateway.match_join`：校验 JWT 已通过 → 查房间 → 恢复 `clientConnected = true` + 取消定时器 + 更新 `userIdToClient` → 立即回发 `match_restore {remainingSec, myScore, opponentScore, grid, size, opponent}`（若对局已结束则回 `match_end`）
- **断线期间提词不补发**（客户端队列丢弃，30s 窗口内影响可接受，技术债登记）

## 7. 消息协议（JSON，在迭代 5 基础上新增）

**客户端 → 服务端**：
```json

```

**服务端 → 客户端**：
```json
{ "event": "match_start", "data": { "matchId": "uuid", "grid": [["字",...]], "size": 5, "duration": 180, "mySid": "uuid", "opponent": { "nickname": "玩家xxx", "rankTier": 1 } } }
{ "event": "match_countdown", "data": { "count": 3 } }
{ "event": "match_tick", "data": { "remainingSec": 120, "myScore": 45, "opponentScore": 60, "myCombo": 3, "opponentCombo": 1 } }
{ "event": "match_opponent_score", "data": { "delta": 5, "total": 60 } }
{ "event": "match_restore", "data": { "remainingSec": 100, "myScore": 30, "opponentScore": 20, "grid": [...], "size": 5, "opponent": {...}, "mySid": "uuid" } }
{ "event": "match_end", "data": { "matchId": "uuid", "winnerUserId": 1, "my": { "score": 120, "rareCount": 3, "maxCombo": 8, "foundWords": [...] }, "opponent": { "score": 100, "rareCount": 2, "maxCombo": 5, "foundWords": [...] } } }
```

**HTTP API（JWT）**：
| API | 说明 |
|---|---|
| `POST /match/queue` | 入队（默认 standard） |
| `GET /match/queue` | 轮询：queued / matched / timeout |
| `DELETE /match/queue` | 取消排队 |

## 8. 前端设计

### 8.1 大厅首页（新增 `client/src/pages/Home/index.vue`，GDD §6.1 P0）

- 入口聚合：**单人闯关**（→ Chapters）、**实时对战**（→ Battle）、**图鉴**（→ Pokedex）、**退出登录**（→ Login）
- `pages.json` 注册 `pages/Home/index`；`Login` 登录成功与已登录跳转改为 `reLaunch /pages/Home/index`（决策 #9）
- Chapters 页保持现状（header 图鉴/退出保留，不重复改）

### 8.2 对战页（新增 `client/src/pages/Battle/index.vue`）

三阶段状态机（`phase: 'queuing' | 'countdown' | 'playing' | 'finished'`）：

1. **queuing**：匹配动画 + 取消按钮；`setInterval` 1s 轮询 `GET /match/queue`；收到 `matched` → 切 countdown；收到 `timeout` → 提示"未匹配到对手，请重试"；WS 收到 `match_start` 同样触发（双通道兜底）
2. **countdown**：3-2-1 大字（`match_countdown`）
3. **playing**：复用 `GridBoard`（同单人），顶部双分数条（我/对手）+ 倒计时 + 对手得分飘字（`match_opponent_score`）+ 断线提示条"连接断开，重连中..."（WS onClose 置状态，onOpen/`match_restore` 清除）
4. **finished**：结算视图（复用 Result 页视觉风格：胜负文案、双方分数、稀有词数、最高连击、我方 foundWords 列表）；按钮"返回大厅"

### 8.3 store 扩展（`client/src/store/game.ts`）

新增状态：`matchMode`、`matchId`、`opponent`（nickname/rankTier/score）、`mySid`、`matchEnd`（胜负+双方数据）、`matchPhase`

- `submitSelection` 不变（统一 `submit_word`，sid 为对战返回的 `mySid`）
- `handleWsMessage` 增加 `match_start/match_countdown/match_tick/match_opponent_score/match_restore/match_end` 分发
- 对战结束 `match_end` → 存 `matchEnd` → 页面切 finished
- `restart/abandon` 清理对战状态；离开 Battle 页时 `DELETE /match/queue`（若在排队）

### 8.4 socket.ts

无改动（`connectSocket/sendWs` 通用；`match_join` 用 `sendWs` 发送）。

## 13. 实现补充（联调发现，v1.1 增补）

| # | 问题 | 决策/修复 |
|---|---|---|
| 1 | bigint 列 userId 经 JWT 为字符串，连接注册 Map key 为 `"3"` 而广播用数字 `3` → 广播失配 | GameGateway 连接时 `Number(payload.userId)` 统一数字 |
| 2 | GameModule ⇄ MatchModule 双向 forwardRef 下 gateway 实例归属不确定，连接注册与广播可能落到不同对象 | **广播与连接映射收归 MatchService 实例**（`userClients` + `registerClient/unregisterClient/broadcastToUser`），GameGateway 只做转发，不再自行持有映射 |
| 3 | 断线 30s 超时仅触发 finishMatch 按分数结算，断线方可能因分高反而胜 | `finishMatch(matchId, forfeitUserId?)`：断线方强制判负（胜者为对方，对齐 GDD §4.2.2） |
| 4 | 重复入队（页面残留排队状态）导致自己配对自己 | `queue()` 入队前先 `cancelQueue(userId)` 清理旧排队残留 |
| 5 | 对战页 GridBoard 被 flex 布局拉高（非正方形），hitTest 行索引越界无法提词 | Battle 页 GridBoard 外包 `aspect-ratio: 1/1` 正方形容器 |
