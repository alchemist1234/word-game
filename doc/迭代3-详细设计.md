## 2. 连击系统设计（核心）

### 2.1 规则（对齐 GDD §2.4.3）

- 玩家找到上一个有效词后 **10 秒内**找到下一个有效词，连击数 +1
- 连击系数 = `1 + 0.1 × min(连击数, 10)`（封顶 ×2.0）
- 超时（>10 秒未找词）则连击数清零
- **无效词/重复词不打断连击也不推进连击**（连击只在有效新词时演进）
- 计分 = `round(字数基础分 × 稀有度系数 × 连击系数)`

### 2.2 连击演进模型

| 事件 | 判定 | combo | 系数 |
|---|---|---|---|
| 第 1 个有效词 | 无 lastWordAt | 0 | ×1.0 |
| 第 2 个有效词（≤10s） | 间隔达标 | 1 | ×1.1 |
| 第 3 个有效词（≤10s） | 间隔达标 | 2 | ×1.2 |
| 第 N 个有效词（≤10s） | 间隔达标 | N-1（封顶 10） | 1+0.1×min(N-1,10) |
| 间隔 >10s | 超时 | 0（重置） | ×1.0 |

### 2.3 服务端实现（check.ts + game.service.ts）

`check.ts` 增加纯函数：

```typescript
/** 连击系数：1 + 0.1 × min(combo, 10)，封顶 ×2.0 */
export function calcComboMultiplier(combo: number): number {
  return 1 + 0.1 * Math.min(combo, 10)
}

/** 计分（含连击系数）：round(基础分 × 稀有度 × 连击系数) */
export function calcScore(length: number, rarity: Rarity, comboMultiplier = 1): number {
  const base = BASE_SCORE[length] ?? 35
  return Math.round(base * RARITY_MULT[rarity] * comboMultiplier)
}
```

`game.service.ts` 的 submitWord 维护连击：

```
提交有效词时：
  now = Date.now()
  if (session.lastWordAt && now - lastWordAt <= 10000) {
    combo = Math.min(session.combo + 1, 10)
  } else {
    combo = 0  // 超时或首个词，重置
  }
  multiplier = calcComboMultiplier(combo)
  score = calcScore(length, rarity, multiplier)
  // 更新会话
  session.combo = combo
  session.maxCombo = Math.max(session.maxCombo, combo)
  session.lastWordAt = now
```

### 2.4 计分示例（对齐 GDD §2.4.4，含连击）

| 顺序 | 词 | 基础分×稀有度 | combo | 系数 | 得分 |
|---|---|---|---|---|---|
| 1 | 朋友（2 common） | 2×1.0 | 0 | ×1.0 | 2 |
| 2 | 犹豫（2 normal） | 2×1.3 | 1 | ×1.1 | round(2.86)=3 |
| 3 | 春暖花开（4 idiom） | 10×2.5 | 2 | ×1.2 | 30 |
| 4 | 守望相助（4 idiom） | 10×2.5 | 3 | ×1.3 | round(32.5)=33 |

> 单测必须覆盖上表 4 个用例。

## 4. API 扩展

### 4.1 `POST /game/word` 响应扩展

```json
// 成功
{
  "valid": true,
  "score": 30,
  "rarity": "idiom",
  "totalScore": 35,
  "combo": 2,
  "comboMultiplier": 1.2,
  "comboRemainingMs": 10000

```

- `combo`：当前连击数（UI 显示）
- `comboMultiplier`：本次系数（飘字显示 ×1.2）
- `comboRemainingMs`：本次连击窗口剩余时间（前端倒计时用，服务端成功找词后固定返回 10000）

### 4.2 `POST /game/end` 响应扩展

```json
{
  "score": 120,
  "maxCombo": 5,
  "potentialCount": 42,
  "foundWords": [{ "word": "中国", "score": 2, "rarity": "common" }, ...]
}
```

- `maxCombo`：本局最高连击
- `potentialCount`：网格潜在词池数（前端算覆盖率：foundWords.length / potentialCount）

## 5. 网格生成难度校准（server/src/grid-gen/grid-gen.ts）

### 5.1 现状
`generateGrid` 生成后计算 potentialWords，但**不校验潜在词池区间**。由于填充字随机，潜在词池大小不可控（可能过小或过大）。

### 5.2 校准策略（简单版，技术债 #5 部分）

```
generateGrid(difficulty, dictionary, trie):
  cfg = DIFFICULTIES[difficulty]  // 含 potentialMin/potentialMax
  多轮生成（如 MAX_ROUNDS = 10）：
    每轮：回溯生成网格 → 填充 → 算 potentialCount
    记录 (grid, potentialCount)
  选择：
    若有落在 [potentialMin, potentialMax] 的 → 返回该网格
    否则 → 返回 potentialCount 最接近区间中值的网格
  兜底：仍失败（词库/难度极端）→ 返回最接近的 + 记 warning
```

### 5.3 难度参数（对齐 GDD §3.2.3，已有 DIFFICULTIES）

| difficulty | size | potentialMin | potentialMax |
|---|---|---|---|
| easy | 4 | 15 | 25 |
| standard | 5 | 30 | 50 |
| hard | 6 | 60 | 100 |

### 5.4 校准单测

- standard 生成 10 次，潜在词池至少 80% 落在 [30, 50] 区间（简单校准下允许少量偏差，技术债 #5 记录）
- 生成耗时 < 1s（预生成网格池可容忍）

> 说明：填充字组合优化（让填充更可能成词/控制丰度）留迭代 5，本轮只做"重试选优"。

## 8. 音效系统（client/src/utils/sound.ts）

### 8.1 H5：Web Audio API 合成（无需音频文件）

```
AudioContext + OscillatorNode，短音合成：

playSuccess()   叮    sine 880Hz, 0.15s, 指数衰减
playIdiom()     编钟  sine 523Hz + 784Hz 双音, 0.4s
playFail()      低沉  square 110Hz, 0.12s
playCombo(n)    递进  频率 = 440 + n×55 Hz（n 连击数）, 0.15s
```

- 模块级单例 AudioContext（首次用户交互后创建，规避浏览器自动播放限制）
- 音量适中（gain 0.3），连击音阶随 n 升高

### 8.2 小程序端（#ifdef MP 分支）

- `#ifdef H5` Web Audio 合成；`#ifdef MP-WEIXIN` 用 `uni.createInnerAudioContext` + 音频文件或先 `uni.vibrateShort` 占位
- 音频文件资源留迭代 6 真机调试时补（技术债）

### 8.3 触发时机（Game 页）

| 有效成语 | playIdiom |

## 10. 数据流与状态流转（连击）

```
[Game] 找词成功
  → store.submitSelection()
    → POST /game/word
      → 服务端：validatePath → 拼字 → 词库 → 去重
      → 连击判定（lastWordAt 间隔 ≤10s? combo+1 : combo=0）
      → score = round(base × rarity × comboMultiplier)
      → 更新 session（combo/maxCombo/lastWordAt/score）
      → 返回 { valid, score, rarity, totalScore, combo, comboMultiplier, comboRemainingMs }
  → store 更新 combo/comboMultiplier/score/foundWords
  → UI：连击条显示 + 10s 倒计时启动 + 飘字（×系数）+ 音效（success/idiom + combo 递进）

[Game] 10s 倒计时归零
  → 前端连击条隐藏（combo 显示归零）
  → 服务端下次 submitWord 判定间隔超时 → combo 重置（一致性吻合）

[Result] 结算
  → POST /game/end
  → 返回 { score, maxCombo, potentialCount, foundWords }
  → 显示最高连击 + 覆盖率（foundWords.length / potentialCount）
```
