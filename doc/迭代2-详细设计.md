## 1. 概述

### 1.1 目标
搭建后端三件套（Nest.js + PostgreSQL + Redis）与 Go 网格生成服务，导入真实词库（5000 词），实现服务端权威的网格生成与提词计分。前端改为调后端 API。

### 1.2 可运行状态
前端打开后从后端拉取一张服务端生成的 5×5 网格（保证可解，潜在词池 30-50），玩家连线提交后由后端校验并返回计分；网格质量明显提升。仍然是"单局 vs 时钟"。

### 1.3 范围
- **In**：Nest.js + PostgreSQL + Redis 搭建、词库导入（5000 词）、Go 网格生成服务 v1（可解性 + 潜在词池）、前端接后端 API、提词/计分服务端权威、网格池预生成
- **Out**：无账号、无对战、无连击、无闯关结构

### 1.4 技术债偿还
- #1 网格生成换 Go 服务端版 ✓
- #2 词库扩到 5000 ✓
- #3 提词/计分服务端权威 ✓

### 1.5 对齐 GDD

## 2. 整体架构

### 2.1 三服务职责划分

| 服务 | 职责 | 理由 |
|---|---|---|
| **Go grid-service** | 词库内存索引（Trie）、网格生成（回溯）、潜在词池计算（DFS 枚举） | CPU/内存密集，Go 并发与性能优 |
| **Nest.js server** | API 网关、提词校验（查 PG）、计分、网格池管理（Redis+PG）、对局会话 | 业务逻辑，TS 全栈，生态成熟 |
| **PostgreSQL** | 词库权威存储、网格池持久化 | 关系型，GIN 索引辅助词库检索 |
| **Redis** | 网格池快速取用、对局会话状态、已找词去重 | 内存读写，实时性 |

**关键决策**：
- **Go 只做计算密集**（生成、枚举），不碰业务。提词校验在 Nest.js（查 PG + 路径校验，简单）。
- **Go ↔ Nest.js 用 HTTP/JSON**（非 gRPC）。迭代 2 MVP 求简，gRPC 留待高并发。GDD §7 允许 gRPC/HTTP 双选。
- **词库**：PG 存权威数据，Go 启动时从 PG 加载到内存 Trie（一次加载，常驻）。

### 2.2 通信拓扑

```
前端(uni-app) ──HTTP── Nest.js ──HTTP── Go grid-service
                        ├── PostgreSQL（词库/网格池）
                        └── Redis（网格池/会话）
```

### 2.3 本地开发启动顺序
1. `docker-compose up`（PostgreSQL + Redis）
2. `cd grid-service && go run .`（Go 服务，加载词库到内存，监听 :8081）
3. `cd server && npm run start:dev`（Nest.js，监听 :3000，启动网格池补充 cron）
4. `cd client && npm run dev:h5`（前端，代理 /api 到 :3000）

## 4. 数据模型

### 4.1 PostgreSQL

#### 4.1.1 `dictionary` 词库表（对齐 GDD §7.4.5）

```sql
CREATE TABLE dictionary (
  word       VARCHAR(16) PRIMARY KEY,
  length     SMALLINT NOT NULL,
  frequency  REAL NOT NULL,          -- 0~1 归一化词频
  rarity     VARCHAR(8) NOT NULL,    -- common/normal/rare/idiom
  tags       JSONB DEFAULT '[]',
  chars      JSONB NOT NULL,         -- 拆字数组 ["春","暖","花","开"]
  meaning    TEXT
);
CREATE INDEX idx_dict_chars   ON dictionary USING GIN (chars);
CREATE INDEX idx_dict_rarity  ON dictionary (rarity);
CREATE INDEX idx_dict_length  ON dictionary (length);
```

#### 4.1.2 `grid_pool` 预生成网格表

```sql
CREATE TABLE grid_pool (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  size            SMALLINT NOT NULL,
  difficulty      VARCHAR(16) NOT NULL,    -- easy/standard/hard
  grid            JSONB NOT NULL,          -- [["中","国",...],...]
  target_words    JSONB NOT NULL,          -- 服务端持有
  potential_count INT NOT NULL,            -- 潜在词池大小
  potential_words JSONB NOT NULL,          -- 全部潜在词（供 AI/校准用）
  status          VARCHAR(16) DEFAULT 'available',  -- available/used
  created_at      TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_gridpool_avail ON grid_pool (difficulty, status);
```

### 4.2 Redis 结构

| Key | 类型 | 内容 | TTL |
|---|---|---|---|
| `grid_pool:{difficulty}` | List | 可用网格的 UUID（RPUSH 生产，LPOP 消费） | 持久 |
| `grid:{uuid}` | String(JSON) | 网格详情（grid/targetWords/potentialCount），缓存 PG | 1h |
| `match_session:{sid}` | Hash | { gridUuid, grid, targetWords, score, startedAt } | 10min（对局时长+缓冲） |
| `match_session:{sid}:found` | Set | 已找到的词（去重） | 同上 |

### 5.2 词库内存索引（trie.go）

启动时从 PG `dictionary` 表加载全部词，构建：
- **Trie**：按字的序列建前缀树，支持 `HasPrefix(prefix)`（剪枝）和 `HasWord(word)`（查词）
- **chars 倒排**：`map[char][]*DictWord`，网格生成时按字找候选词

```go
type TrieNode struct {
    children map[rune]*TrieNode
    isWord   bool
    word     string  // 完整词（叶子时填充）
}

type Trie struct{ root *TrieNode }

func (t *Trie) Insert(word string)
func (t *Trie) HasPrefix(prefix string) bool  // 潜在词池 DFS 剪枝
func (t *Trie) HasWord(word string) bool
```

### 5.3 网格生成算法（grid.go）

迁移迭代 1 `gridGen.ts` 逻辑到 Go，对齐 GDD §3.2.2：

```
输入：size, difficulty（决定 minTarget/candidateCount/idiomRatio）

1. 按 difficulty 选候选词集 W（从内存词库，idiomRatio 控制成语占比）
2. grid = size×size 空
3. for w in W:
     path = findPath(grid, w.chars)  // 回溯找相邻路径，字可复用
     if path: placeOnGrid(grid, w.chars, path); placed.append(w)
     if len(placed) >= candidateCount: break
4. if len(placed) >= minTarget:
     fillEmpty(grid, FILLER_CHARS)
     potential = computePotential(grid, trie)  // 潜在词池
     return { grid, targetWords: placed, potential }
5. else: 重试（最多 maxRetries），仍失败则递减 minTarget
```

难度参数（对齐 GDD §3.2.3）：

| difficulty | size | minTarget | candidateCount | idiomRatio | 潜在词池目标 |
|---|---|---|---|---|---|
| easy | 4 | 5 | 7 | 0.10 | 15-25 |
| standard | 5 | 8 | 12 | 0.25 | 30-50 |
| hard | 6 | 14 | 20 | 0.40 | 60-100 |

### 5.4 潜在词池计算（potential.go）

Boggle 式 DFS 枚举 + Trie 剪枝：

```go
func ComputePotential(grid [][]string, trie *Trie) []string {
    var words []string
    size := len(grid)
    for r := 0; r < size; r++ {
        for c := 0; c < size; c++ {
            dfs(grid, r, c, "", map[[2]int]bool{}, trie, &words)
        }
    }
    return dedup(words)
}

func dfs(grid [][]string, r, c int, prefix string,
         visited map[[2]int]bool, trie *Trie, words *[]string) {
    if visited[[2]int{r, c}] { return }
    prefix += grid[r][c]
    if !trie.HasPrefix(prefix) { return }   // 剪枝：前缀不在词库，停
    if trie.HasWord(prefix) { *words = append(*words, prefix) }
    visited[[2]int{r, c}] = true
    for _, d := range DIRS8 {
        nr, nc := r+d[0], c+d[1]
        if nr>=0 && nr<len(grid) && nc>=0 && nc<len(grid) {
            dfs(grid, nr, nc, prefix, visited, trie, words)
        }
    }
    visited[[2]int{r, c}] = false
}
```

复杂度：5×5、最长 6 字、Trie 剪枝下毫秒级。

### 6.3 API 设计（给前端）

#### `GET /game/grid?size=5&difficulty=standard`

- 从 Redis `grid_pool:standard` LPOP 一个 UUID
- 取网格详情（Redis `grid:{uuid}` 缓存或查 PG）
- 创建 match_session（Redis），存 grid + targetWords + score=0 + startedAt
- 返回（**不下发 targetWords/potentialWords**，防作弊）：

```json
{
  "matchSessionId": "uuid",
  "grid": [["中","国",...],...],
  "size": 5,
  "duration": 180
}
```

#### `POST /game/word`

```json
// Req
{ "matchSessionId": "uuid", "word": "中国", "cells": [{"row":0,"col":0},{"row":0,"col":1}] }

// Resp (valid)
{ "valid": true, "score": 2, "rarity": "common", "totalScore": 12, "combo": 0 }

// Resp (invalid)
{ "valid": false, "reason": "not_in_dict" | "path_invalid" | "duplicate" }
```

服务端流程：
1. 取 match_session（Redis），校验 sessionId 有效
2. 路径校验：cells ≥2、逐对 8 向相邻、无重复格（迁移迭代1 wordCheck 逻辑）
3. 查 PG dictionary：词存在？取 rarity/length
4. 查 Redis `match_session:{sid}:found`：去重
5. 计分：`round(基础分[rarity] × 稀有度系数[length])`（迁移迭代1 score 逻辑，本迭代无连击）
6. 更新会话：found Set 加词、score 累加
7. 返回

#### `POST /game/end`

```json
{ "matchSessionId": "uuid" }
// Resp
{ "score": 120, "foundWords": [{"word":"中国","score":2,"rarity":"common"},...] }
```

结束会话，返回结算数据。前端时间到时调用。

### 6.4 网格池管理（grid-pool.service.ts）

- **取用**：`GET /game/grid` 时从 Redis List LPOP UUID
- **补充**：Nest.js `@nestjs/schedule` cron，每 10 分钟检查各 difficulty 的 Redis List 长度，低于阈值（如 20）则调 Go `/generate` 生成补充，写 PG + RPUSH Redis
- **持久化**：生成的网格写 PG grid_pool（status=available），Redis 是 PG 的快速索引
- **标记已用**：取用后 PG status 改 used（异步，避免阻塞取用）

```typescript
@Cron('*/10 * * * *')
async replenishPool() {
  for (const diff of ['easy', 'standard', 'hard']) {
    const count = await this.redis.llen(`grid_pool:${diff}`)
    if (count < THRESHOLD) {
      const need = THRESHOLD - count
      for (let i = 0; i < need; i++) {
        const grid = await this.gridClient.generate(5, diff)
        const id = uuid()
        await this.gridPoolRepo.save({ id, ...grid, status: 'available' })
        await this.redis.rpush(`grid_pool:${diff}`, id)
      }
    }
  }
}
```

```
  rare       if frequency < 0.10
  normal     if 0.10 <= frequency < 0.40
  common     if frequency >= 0.40
```

## 10. 实现顺序建议（给 AI coding）

按依赖序，每步可独立验证：

1. **docker-compose + PG/Redis**：`docker-compose up`，确认两服务可连
2. **Nest.js 骨架**：项目初始化、TypeORM 连 PG、ioredis 连 Redis、健康检查端点
3. **dictionary 表 + entity**：建表，TypeORM entity
4. **词库源数据 + 导入脚本**：整理 5000 词到 `data/dictionary.json`，写 import.ts，导入 PG，验证各 rarity 分布
5. **Go 服务：Trie + 词库加载**：从 PG 读词库建 Trie，`/health` 返回 dictSize
6. **Go 服务：网格生成**：迁移回溯算法，`/generate` 返回 grid + targetWords
7. **Go 服务：潜在词池**：DFS 枚举 + Trie 剪枝，`/generate` 返回 potentialCount
8. **Go 单测**：迁移可解性验证到 grid_test.go
9. **Nest.js：grid-client + grid-pool**：调 Go 生成，存 PG + Redis，cron 补充
10. **Nest.js：game API**：`/game/grid`（取池+建会话）、`/game/word`（校验+计分）、`/game/end`
11. **Nest.js 单测**：迁移提词/计分单测到 jest
12. **前端改造**：删 core 逻辑，加 api 层，改 store，配 vite 代理
13. **端到端联调**：前端拉网格 -> 连线提交 -> 后端校验计分 -> 结算
14. **验收**：逐条过 §12 checklist

## 11. 防作弊（对齐 GDD §3.3）

| 环节 | 措施 |
|---|---|
| 网格 | 服务端生成，下发仅 grid 矩阵，**不下发 targetWords/potentialWords** |
| 提词校验 | 服务端查 PG + 校验路径，客户端无法伪造 |
| 计分 | 服务端计算，客户端仅显示 |
| 会话 | match_session 存 Redis，有时效（10min），防回放 |
