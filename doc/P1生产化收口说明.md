# P1 生产化收口说明

> 本轮 P1 实现记录（2026-09-25）。本文件记录实际落地边界，不替代 GDD/迭代设计。

## 1. Schema 与发布

- `server/src/migrations/` 提供可重复执行的 baseline 与 P1 扩展 migration。
- 开发环境：`DB_SYNCHRONIZE=true`（默认，仅开发）。
- 生产环境：`DB_SYNCHRONIZE=false`，先执行 `npm run migration:run`，再启动应用。
- `npm run schema:log` 必须无输出；migration job 单独运行，应用副本不自动跑 DDL。
- 词库导入改为默认增量 `ON CONFLICT DO NOTHING`；`--replace` 仅允许非生产显式使用。

## 2. 结算与副作用

- `game_settlements` 与 `outbox_events` 在同一 PostgreSQL 事务写入。
- outbox worker 使用 `FOR UPDATE SKIP LOCKED`、租约、退避重试；排行榜使用 max-ZSET Lua，成就检查使用唯一键幂等。
- 结算请求仍可触发一次即时 dispatch；失败不会回滚已提交的结算账本，由 worker 补偿。
- `FAULT_INJECTION_POINTS` 仅用于测试/演练，默认 no-op，不提供生产 HTTP 故障接口。

## 3. Redis 队列

- 匹配队列按 `casual/ranked`、人数、段位隔离。
- 入队、claim 字段和队列扫描锁使用 Redis token/`SET NX EX` + Lua compare-and-delete；进程崩溃后 claim 租约过期可重试。
- 当前房间、连接和计时器仍是单实例内存状态。多实例部署必须将 `/match` 与 `/api/game/ws` 固定到同一 match coordinator；Redis 锁不等于房间多实例外置。

## 4. 9-1 收词安全决策

审核管理端上线前，`WORD_APPLY_AUTO_MERGE_ENABLED=false` 为默认值：申请只进入 `pending`，不会自动写入正式词库。基础 blocklist、DTO/路径边界、CST 日限、事务和幂等索引已启用。启用自动合并前必须完成人工审核能力与运营流程。

## 5. 运行检查

```bash
cd server
npm run migration:show
npm run migration:run
npm run schema:log
npm test
npm run build
```

生产启动前必须设置随机 `JWT_SECRET`；`NODE_ENV=production` 时若 `DB_SYNCHRONIZE=true` 或 JWT secret 为空，服务会拒绝启动。
